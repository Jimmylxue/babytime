# 育娃手记 · 管理后台看板方案

## 总体架构
- **后端**：`apps/server` 新增 `AdminModule`，提供 `/api/admin/*` 接口（统计聚合 + 管理员登录 + 公告管理 + 用户列表），全部查现有 MySQL 表，不加新表。
- **前端**：新增 `apps/admin`（Vite + React 18 + Ant Design 5 + ECharts），构建后由 NestJS 服务托管在 `/admin` 路径（HashRouter，无需服务端路由回退）。部署仍是单个 PM2 进程，线上访问 `http://服务器:3000/admin`。
- **鉴权**：环境变量配置单账号 `ADMIN_USERNAME` / `ADMIN_PASSWORD`，登录后签发独立的 admin JWT（用独立的 `ADMIN_JWT_SECRET` 签名，与小程序用户 JWT 完全隔离，互相不可越权）。有效期 7 天。
- **返回格式**：沿用现有 `{ code, message, data }` 包装。

## 看板内容
1. **概览 KPI 卡片**：累计用户/今日新增、累计宝宝数、累计记录/今日新增、今日活跃用户（当日有记录的去重用户）、近7日活跃用户、AI 便便分析累计次数（`diaper_analysis` 非空的记录数）、累计照片数。
2. **趋势图**（7/30/90 天切换，折线图）：每日新增用户、每日新增记录、每日活跃用户(DAU)，按 `created_at` 日期分组聚合，缺数日期补 0。
3. **分布图**：记录类型分布饼图（12 类，中文标签）、宝宝性别分布饼图。
4. **用户列表页**：分页表格（头像、昵称、openId 脱敏、宝宝数、记录数、注册时间），按注册时间倒序，支持昵称搜索。
5. **公告管理页**：目前公告是启动时写死播种的，这里补上管理界面 —— 列表、新建、编辑、启用/下线开关。发布新公告自动生成新 ID（保持现有"公告 ID 即已读版本号"的约定）。

## API 设计（全部挂 AdminGuard）
- `POST /api/admin/auth/login` — 账号密码登录，返回 token
- `GET /api/admin/stats/overview` — KPI 汇总
- `GET /api/admin/stats/trends?days=7|30|90` — 每日新增用户/新增记录/DAU
- `GET /api/admin/stats/distribution` — 记录类型 + 性别分布
- `GET /api/admin/users?page=&pageSize=&keyword=` — 用户分页列表（含宝宝数/记录数聚合）
- `GET|POST /api/admin/announcements`、`PUT /api/admin/announcements/:id` — 公告管理

## 新增/修改文件

**后端新增**（`apps/server/src/modules/admin/`）：
- `admin.module.ts`、`admin.controller.ts`
- `admin-auth.service.ts`（登录校验 + 签发 token）、`admin-stats.service.ts`（聚合查询，参照现有 record.service 的 raw SQL 风格）
- `admin-announcement.service.ts`（复用 Announcement 实体直接 CRUD）
- `strategies/admin-jwt.strategy.ts`、`guards/admin-jwt.guard.ts`
- `dto/`：登录、创建/更新公告 DTO

**后端修改**：`app.module.ts` 注册 AdminModule；`main.ts` 若 `apps/admin/dist` 存在则用 express.static 托管到 `/admin`（不存在则跳过，不影响本地开发）；`.env.example` 增加 `ADMIN_USERNAME/ADMIN_PASSWORD/ADMIN_JWT_SECRET`。

**前端新增**（`apps/admin/`）：`package.json`、`vite.config.ts`（base=/admin/，dev 代理 /api → localhost:3000）、`tsconfig.json`、`index.html`、`src/`（main.tsx、App.tsx 路由+登录守卫、axios 封装、AdminLayout 侧边栏、Login/Dashboard/Users/Announcements 四个页面、类型定义）。

**部署相关修改**：根 `package.json` 加 `dev:admin`/`build:admin`，`build` 改为 admin+server 一起构建；`server.sh` 部署流程加 `build:admin` 步骤。

## 部署方式（改完后）
服务器上照旧执行 `bash server.sh`，部署完成后浏览器打开 `http://服务器地址:3000/admin`，用 `.env` 里配置的账号密码登录即可，不用再直连数据库。

## 验证
本地起 MySQL + `pnpm dev:server` + `pnpm dev:admin` 走一遍登录和各页面；再执行完整构建确认产物和托管路径正常。若本地依赖安装/数据库不可用，会明确说明验证到哪一步。
