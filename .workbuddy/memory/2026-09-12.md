## 家庭成员修改昵称（备注名）功能

背景：用户建议「家庭成员管理里可以改成员昵称，便于管理」，属 P1 家庭协作。

### 设计结论（重要）

- 备注名是**家庭内**的称呼，绝不能改写 `users.nickname`（全局昵称，影响其它场景展示）。
- 单独新建 `family_member_aliases` 表，键为 `(family_owner_id, target_user_id)` 唯一。
  原因：家庭创建者自己**没有** family_members 记录（列表里的「创建者」是运行时拼出来的），
  只有独立表才能让「创建者改家人」「家人改创建者」「自己改自己」走同一套逻辑。
- 权限：创建者可改任意成员（含自己）；普通成员只能改自己。
- 传空串 = 恢复默认（删备注，回落微信昵称）。
- 备注名走 `ContentSecurityService.checkUserTexts`，与宝宝名/用户昵称同一口径。
- 移除成员、退出家庭时清理备注行。

### 本地自测工具（新增）

`apps/server/scripts/family-nickname-check.js` → `npm run check:family` / `check:family:clean`
- 背景：本地只有一个微信号，没法真邀请第二个用户；而「改成员昵称」只依赖一条
  `family_members` 记录，所以直接造一个 `open_id = local_seed_family_member` 的假家人即可。
- 零额外依赖：mysql2（已在 apps/server）+ node crypto 自签 JWT（HS256，payload `{sub, openId}`）
  + 全局 fetch 打接口；.env 手工解析。
- 12 项断言含：成员列表含创建者+假家人、**权（非本家庭成员 400）、20 字上限、成员不能改别人、传空串恢复默认。
- **实测结果 12/12 通过**（真实库 + 127.0.0.1:3000 上运行中的服务）。

### 环境中查到的事实（next time 直接用）

- 本地 MySQL 在跑（127.0.0.1:3306），客户端在 `/opt/homebrew/bin/mysql`（不在 PATH），
  密码在 `.env` 的 `DB_PASSWORD`，用 `MYSQL_PWD` 环境变量传；**没有** `mysqldump`/docker。
- 服务端常驻 3000 端口且是 watch 模式：改完实体它会自动 reload 并 synchronize 建表，
  所以新表 `family_member_aliases` 会自动出现，不用手动建。
- macOS 自带 grep 不支持 BRE 的 `\|`，要用 `grep -E`，否则会误判成 0 匹配。
- `sass` 直接给「输入 输出」两个路径参数会退出码 66，改成重定向 `> out.css` 正常。

### 待办 / 已知点

- 上线前需在服务器执行 `docs/family-member-nickname.sql`，否则接口报 table doesn't exist。
- 迁移 SQL 里**不要**写 COLLATE：本地 synchronize 建出来的是 `utf8mb4_0900_ai_ci`，
  硬写 `utf8mb4_unicode_ci` 会和其他表排序规则不一致（已改掉）。
- 生产部署顺序（已写进 docs/ops-runbook.md 的「已执行记录」）：
  `git pull`（先拿到 SQL 文件）→ `bash backup-db.sh pre-deploy` → `mysql ... < docs/family-member-nickname.sql`
  → `bash server.sh`。因为纯新增表且旧代码不读它，可以「先建表再发版」，中间无空窗期；
  回滚只撤销代码，新表可保留。**注意**：server.sh 自带 `git pull origin main`，
  所以本地必须先 commit + push 才能部署。
- `family-nickname-check.js` 的 `clean` 只删 `open_id = local_seed_family_member` 关联的数据，
  不会碰用户自己账号产生的备注（有意为之，避免误删用户真实设置）。
- 备注只有一行记录：「创建者备注」与「成员自己改名」是同一行，谁最后改以谁为准。
- 创建者直接删除宝宝档案时（baby.service.remove），备注行会留孤儿数据（不影响功能，未做级联）。
- 创建者如果没有任何家人加入，`getFamilyMembers` 返回空数组 → 页面看不到自己那条，
  因此「给自己设备注」在单人家庭里其实用不上（未改动该既有行为）。
- 环境里的 `nest build` 会被 safe-delete 守卫拦（dist 递归 203 个文件 > 阈值 50），
  服务端校验改用 `npx tsc --noEmit -p tsconfig.json`。
