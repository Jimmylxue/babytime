## 待发布 · 2026-11-09（第三波）

本轮 4 项（原计划的「亲喂左右侧计时」**主动跳过**，原因见末尾）：

1. **#5 记录导出为 Excel（.xlsx）—— 全链路统一 Excel，不使用 CSV**
   - `GET /record/export/:babyId?days=N` 返回 **base64 编码的真 xlsx**
   - 小程序 `writeFileSync(..., 'base64')` 写本地再 `openDocument({fileType:'xlsx'})` 打开
   - **不走 `downloadFile`**：省掉域名白名单配置和 JWT header 的特殊处理（少一个失败点）
   - ⚠️ **为什么不用 CSV**：微信 `wx.openDocument` 的 `fileType` 白名单只有
     doc/docx/xls/xlsx/ppt/pptx/pdf，**没有 csv**。CSV 写出来也打不开，
     只能弹「请转发到电脑」—— 真机同样如此，不是模拟器问题
   - 代码里已无 CSV：方法名 `exportRecordsExcel` / API `exportExcel` / 文件 `.xlsx`
   - 仅保留「为什么不用 CSV」的注释（防止以后有人改回去踩同一个坑）
   - 自研零依赖 xlsx 生成器 `apps/server/src/common/xlsx.ts`（zip + 4 个 XML，用内置 zlib 压）
     —— 只为 11 列纯文本表格装 exceljs（几 MB）不划算
   - 「我的」页入口图标从 emoji 📄 改为自绘 SVG `export-table.svg`（与相邻图标同一 24×24 / 2px 线宽风格）
2. **#7 疫苗补种提醒**（新页面 `pages/tool/vaccine-catchup`）
   - 按参考日算「哪几针过了参考日还没登记接种」「两周内该打」
   - 纯时间提示，**不给补种方案** —— 减毒/灭活间隔差异必须由接种门诊定
   - 算法在 `packages/shared/src/vaccineCatchUp.ts`，前后端共用、可单测
3. **#14 辅食新食物 3 天观察 + 反应标记**
   - `records` 新增 `food_reaction` / `food_is_new` 两列
   - 记录页辅食表单加「吃完怎么样」，选「有反应」时提示停 3 天或咨询医生
   - 首页出现「新食物观察」卡，**只在有正在观察的食物时渲染**，观察期满自动消失
   - 聚合逻辑在 `packages/shared/src/foodObservation.ts`
4. **同时修复**：导出里原本塞了 `# 说明行`（非标准格式，Excel 会当成 1 列的残缺数据），
   已改成说明走返回体的 `note` 字段。改用 xlsx 后这个问题自然消失。

                                            # 11 项：用独立解析器反向读回

补种算法覆盖的边界：

| 场景 | 结果 |
|---|---|
| 跨月/跨年/闰年日期差 | 正确（本地日历，不踩 UTC） |
| 新生儿（今天出生） | 无逾期，只有 dueSoon |
| 全部接种 | 无逾期、无 upcoming、mostUrgent=null |
| 接种一针 | done+1、逾期-1、mostUrgent 顺延 |
| overdueText 措辞 | 不含「必须/延误/异常」 |

辅食观察覆盖的边界：首日/第 3 天/第 4 天、有反应不算 passed、未来日期脏数据跳过、
超过 30 天的老食物不算新食物、前后空格视作同一食物。
