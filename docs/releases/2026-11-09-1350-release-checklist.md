## 待发布 · 2026-11-09（导出范围限制）

### 问题

第三波上线前发现：导出**固定近 365 天**，用户无法选择。
活跃用户日均记 15 条左右，一年就是 **5400+ 条**，必然撞上 3000 行上限 ——
`truncated=true` 时只是弹个 toast，**用户拿到的是一份不完整的数据却不知道**，
拿去分析会得出错误结论。

### 改动

**服务端**（`record-query.service.ts`）

- `GET /record/export/:babyId` 的参数从 `?days=N` 改为 `?startDate=&endDate=`
- 新增 `parseExportRange()`：统一解析 + 校验，所有边界按本地日历日算
- 上限 **31 天**（`EXPORT_MAX_DAYS`），超出直接 **400 拒绝**，不再静默截断
- 未来日期自动夹到今天；只传一头时另一头自动补全
- `MAX_EXPORT_ROWS=3000` 降级为「最后一道防线」（一个月内也可能有极高频记录）

**客户端**（`pages/mine`）

- 点「导出记录表格」先弹**范围选择面板**：快捷 7/14/30 天 + 双日期选择器
- 面板实时显示「共 N 天」，超过 31 天**立刻标红**并提示，不用等点了才报错
- 默认选中最近 31 天
- 日期选择器的 `start`/`end` 互相约束，选不出「开始晚于结束」

### 6. 本轮验证方式

**一个纯逻辑打桩 + 一个真库 e2e，共 46 项全过：**

```bash
node /tmp/verify-wave4/verify-range.cjs    # 19 项：区间解析（直抽真实源码）
node /tmp/verify-wave3/e2e-wave3.cjs       # 27 项：真实库 + 真实 HTTP（含超限拒绝）
```

区间解析覆盖的边界：

| 场景 | 结果 |
|---|---|
| 不传参数 | 默认最近 31 天 |
| 恰好 31 天 | 通过 |
| 32 天 / 一年 | 400 拒绝，文案含「最多 31 天，当前 N 天」 |
| 开始晚于结束 | 400 拒绝 |
| 非法日期字符串 | 不崩，回退默认 |
| 未来 endDate | 夹到今天，不报错 |
| 只传 endDate | 自动往前补 31 天，且不超限 |
| 同一天 | 1 天，允许 |
| 跨月 31 天（2月28天） | 通过 |
| 闰年 2月（29天）31 天 | 通过 |

e2e 实测的 HTTP 行为：

```
✅ 32 天区间被拒（400）→ 导出范围最多 31 天，当前选择了 32 天，请缩小范围
✅ 一年区间被拒 → 400
✅ 30 天区间通过 → 200
✅ 开始晚于结束被拒 → 400
✅ 未来结束日不报错（被夹到今天）→ 文件名 2026-11-01_2026-11-09.xlsx
✅ 不传参数走默认 31 天
```

## 待确认事项

- [ ] **31 天这个上限合不合适**：按日均 15 条算，一个月约 450 行、base64 后 ~50KB，
      弱网也能在 2 秒内完成。如果你想更宽松（比如 3 个月），改
      `EXPORT_MAX_DAYS` 一个常量即可，前后端各一处（已注释标注要同步）
- [ ] 是否要**跨月导出**（比如「上个自然月」）：现在只有「最近 N 天」，
      月初导上个月得手动选日期。要做的话加一个「上个完整月」快捷按钮
- [ ] 范围选择器用的是微信原生 `Picker mode="date"`，样式跟随系统（iOS 是滚轮，
      Android 是日历）。如果要统一视觉需要自绘日历，成本较高，暂不做
- [ ] 导出**没有进度条**：31 天内一般 1~2 秒完成，只有 loading。若以后放宽到
      3 个月以上，需要加进度反馈
