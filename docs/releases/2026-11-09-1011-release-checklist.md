## 待发布 · 2026-11-09（第一波：记录数据可视化补齐）

本轮改动（4 项，全部零新表、零新环境变量、零新增路由）：

1. **统计页补齐 5 个类型 tab，并重排顺序**：辅食 / 喝水 / 用药 / 洗澡 / 户外。
   这 5 类服务端 `getStats` / `getDetail` / `getDetailSummary` 一直支持，只是统计页没给入口，
   用户"记了却看不到"。补齐后每类都配了对应的每日柱状图（14/30 天自动切日历热力格）。
   **顺序按使用频次重排**：喂奶 → 尿布 → 身高 → 体重 → 体温 → 疫苗（这 6 项一屏可见）
   → 睡觉 → 辅食 → 喝水 → 用药 → 洗澡 → 户外。原顺序把身高/体重排到第 6、7 位，疫苗掉到最后。
2. **服务端 `getRecordDetailSummary` 补 `outdoor` 的 `totalDuration`**：
   户外记录本来就存 `duration`（活动时长），汇总时却只对 sleep 返回，统计格会恒为 0。
3. **「本月关注」内容从 12 月龄扩到 72 月龄**（13 组 → 19 组），
   并把取值方式从「数组下标当月龄」改成**显式区间匹配**。
   改动前满 12 个月的宝宝 `getMonthlyTips()` 直接返回 `null`，发现页那一格整个消失。
4. **首页新增「今日概览条」**（一行：今天记了几条 + 类型分布）+ **宝宝卡连续记录天数徽章**。
5. **首页移除「育娃圈」入口**（含 `community-entry` 样式与其专用的 `getSystemConfig()` 调用）。
   发现页的育娃圈入口保留，育娃圈功能本身不受影响。

配套的顺带修复：

- `DayDetailCard` 的统计格新增 water / outdoor 专属分支；
  **辅食 / 用药 / 洗澡**改为「总次数 + 平均间隔 + 最近一次」，
  不再落进睡眠那套「总时长 + 平均清醒间隔」（这 3 类没有 duration，会稳定显示两个假数据）。
- `utils/mock.ts` 的 `MOCK_DETAIL` 补齐 `food/water/medicine/bath/outdoor/vaccine` 六个 key。
  改动前未登录进入「辅食」明细页会因 `MOCK_DETAIL[activeType].items` 取不到而抛 TypeError。
- 示例统计数据补上 `bathCount/outdoorCount/temperatureCount/medicineCount`，未登录预览的新 tab 不再是全空柱子。

**无。** 本轮不新增表、不加列、不改索引。

两处看似需要索引、实际不用的地方（已确认，不要再补 SQL）：

- `getRecordStreak` 走 `SELECT DISTINCT DATE_FORMAT(start_time,'%Y-%m-%d') ... WHERE baby_id = ?`，

- 今日概览条复用 `/record/summary` 里本来就查出来的 `records`，没有新增查询。

### 4. 部署步骤与顺序

1. `bash server.sh`（构建服务端 + 管理后台）
2. `bash mini.sh <版本号> "统计补齐五类记录视图、今日概览、连续记录"`

顺序说明：

- **必须先服务端、后小程序**。小程序新版会读 `summary` 响应里新加的 `streak` 字段，
  服务端没部署时拿到的是 `undefined`，徽章不显示（不会报错，但功能缺失）。
- 反过来**服务端先发不影响旧版小程序**：`streak` 只是多返回一个字段，
  `summary.records` 的排序从默认改为 `startTime ASC` —— 旧版从未消费过这个字段（一直是死数据），
  所以改排序对旧版零影响。
